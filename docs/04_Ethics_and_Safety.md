# Ethics and Safety Policy

## 1. No AI Life-critical Decision Making

RescueMap OS does not make life-or-death decisions for users.

It does not guide users through AI-based indoor escape routing.

## 2. Why We Avoid AI Escape Routing

In a disaster, a building layout may change quickly.

Possible risks:

- collapsed structure
- blocked stairs
- smoke
- flooding
- blackout
- locked doors
- network failure
- outdated indoor map

If an automated system gives a wrong direction, the result may be dangerous.

Therefore, the project focuses on recording location clues and status instead of giving direct escape commands.

## 3. Privacy Principles

- no always-on location tracking
- location is recorded only when the user explicitly shares status
- guardian and institution access must be limited
- admin access logs should be recorded
- post-disaster failure maps should be anonymized
- personal data should be deleted or anonymized after the disaster context ends

## 4. Vulnerable Modes

Vulnerable modes are optional.

They are not labels for classification.

They exist to provide different support flows for different needs.

Examples:

- elderly mode
- disabled mode
- isolated youth mode
- night-return mode
- infection-sensitive mode

## 5. Disclaimer

RescueMap OS does not guarantee rescue success.

It provides clues, status records, and check-in workflows to help people and institutions respond faster.
